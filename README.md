# รู้ทันน้ำ · Thailand Flood Watch

เว็บแอปติดตามสถานการณ์น้ำสำหรับมือถือและคอมพิวเตอร์ แสดงจุดน้ำล้นตลิ่ง พื้นที่น้ำท่วมจากดาวเทียม ถนนน้ำท่วม ประตูระบายน้ำ เขื่อน การจราจรสด และกล้อง CCTV ทั่วประเทศบนแผนที่เดียว ข้อมูลทุกจุดมีเวลาและที่มากำกับ ออกแบบให้ deploy บน **Vercel Hobby** ได้โดยไม่ต้องมีฐานข้อมูล

> ข้อมูลในแอปไม่ได้ยืนยันสภาพน้ำที่บ้านหรือบนถนน อย่าใช้แทนประกาศเตือนภัยของหน่วยงานในพื้นที่

## ความสามารถ

| หัวข้อ | รายละเอียด | ต้องมี key |
|---|---|---|
| สถานีวัดน้ำ | สถานีทั่วประเทศจาก ThaiWater สีตามระดับเทียบตลิ่ง (ล้นตลิ่ง / ใกล้ตลิ่ง / ปกติ / น้ำน้อย / ไม่มีเกณฑ์ / ข้อมูลเก่า) | – |
| จุดน้ำล้นตลิ่ง | หมุดแดงกะพริบพร้อมส่วนต่างเหนือตลิ่ง แถบ "ใกล้คุณ" และแท็บ **เตือนภัย** เรียงจากเสี่ยงมากสุด | – |
| พื้นที่น้ำท่วม | ภาพเรดาร์ดาวเทียมของ GISTDA ผ่าน proxy ฝั่ง server | `GISTDA_API_KEY` |
| ถนนน้ำท่วม | รายงานถนนน้ำท่วมจาก ThaiWater เป็นหมุดและรายการ | – |
| ประตูระบายน้ำ | ระดับน้ำด้านรับ/ด้านระบาย ต่างระดับ บานที่เปิดและเครื่องสูบที่ทำงาน (เมื่อสถานีรายงาน) เรียงจากใกล้คุณ | – |
| เขื่อนและอ่างเก็บน้ำ | อ่างขนาดใหญ่และกลาง: % ความจุปกติตามเกณฑ์กรมชลประทาน ปริมาณน้ำ น้ำไหลเข้า/ระบายรายวัน | – |
| การจราจรสด | เส้นสีตามความเร็วรถ (TomTom) เปิดอัตโนมัติ รีเฟรชทุก 2 นาที | `TOMTOM_API_KEY` |
| กล้อง CCTV | กล้องระดับน้ำ กทม./นนทบุรี/ปทุมธานี/รังสิต และกล้องจราจรทั่วประเทศจาก iTIC / Longdo Traffic กล้องที่มีวิดีโอเล่นสดในรายการได้พร้อมกัน 4 จอ กล้องที่มีแต่ภาพนิ่งอัปเดตทุก 5–10 วินาที กดเพื่อขยายเต็มจอ | – |
| ตำแหน่งของฉัน | GPS (เมื่อผู้ใช้อนุญาต) และหมุดบ้านที่เก็บในเครื่อง ใช้เป็นจุดศูนย์กลางของรายการ "ใกล้คุณ" | – |

**บนมือถือ:** แถบบนแสดงเวลาอัปเดต ต่อด้วยแถบ "ใกล้คุณ: ล้นตลิ่ง · (สถานี)" และตัวเลขสรุป 4 ช่อง เมนูล่าง **แผนที่ · เตือนภัย · น้ำท่วม · ประตูน้ำ · กล้อง · จราจร** แต่ละเมนูเปิดเป็นหน้าเต็มจอ ส่วนหน้าแผนที่มีช่องค้นหาและปุ่ม "ชั้นข้อมูล" สำหรับเปิด/ปิดแต่ละชั้น

**บนคอมพิวเตอร์:** แผงควบคุม · แผนที่ · แท็บข้อมูล อยู่ในหน้าเดียวกัน 3 คอลัมน์

## เริ่มใช้งานในเครื่อง

ต้องใช้ Node.js 20 ขึ้นไป

```bash
npm ci
npm run dev          # http://localhost:3000
```

ตั้ง API key ในเครื่องได้โดยคัดลอก `.env.example` แล้ว export ตัวแปรก่อนรัน `npm run dev` (dev server ไม่อ่านไฟล์ `.env` เอง)

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | dev server เสิร์ฟ `public/` และ `/api/*` แบบเดียวกับ Vercel |
| `npm run typecheck` | ตรวจ type ทั้งโปรเจกต์ด้วย TypeScript (`checkJs` + JSDoc, strict) |
| `npm test` | unit test ของ parser, API และโมดูลหน้าเว็บ (`node --test`) |
| `npm run test:e2e` | ทดสอบใน Chromium จริงทั้ง desktop และ mobile ด้วย Playwright (ครั้งแรกให้รัน `npx playwright install chromium`) |
| `npm run build` | typecheck + ตรวจ import graph และ `modulepreload` (Vercel ใช้คำสั่งนี้) |
| `npm run check` | build + unit test ก่อน push |

GitHub Actions (`.github/workflows/ci.yml`) รัน typecheck, unit test และ build บน Node 20/22 จากนั้นรัน browser test ทุก PR และทุก push เข้า `main`

## Deploy ไป Vercel

1. Import repository ใน Vercel (**Add New → Project**)
2. ตั้ง Framework Preset = **Other**, Output Directory = `public`, Build Command = `npm run build` ถ้า type ผิด build จะล้มและไม่ deploy
3. ตั้ง Environment Variables ตามตารางด้านล่าง แล้วกด **Redeploy** ทุกครั้งที่เพิ่มหรือแก้ตัวแปร
4. ตรวจหลัง deploy:
   - `/api/water` มี `stations`
   - `/api/road-flood` มี `"status": "ok"`
   - `/api/traffic-cameras` มี `cameras`
   - `/api/water-gates` มี `gates` และ `/api/dams` มี `dams` โดยทั้งคู่มี `"status": "ok"`
   - `/api/config` บอกว่าชั้นที่ตั้ง key แล้วเป็น `available: true`

### Environment variables

| ตัวแปร | ใช้ทำอะไร | ถ้าไม่ตั้ง |
|---|---|---|
| `GISTDA_API_KEY` | ชั้นพื้นที่น้ำท่วมจากดาวเทียม key อยู่ฝั่ง server เท่านั้น | สวิตช์ถูกปิดพร้อมคำอธิบาย |
| `GISTDA_FLOOD_PERIOD` | ช่วงภาพ `1day`, `3days` หรือ `7days` | `7days` |
| `TOMTOM_API_KEY` | ชั้นการจราจรสด | สวิตช์ถูกปิด |
| `TRAFFIC_TILE_URL`, `TRAFFIC_ATTRIBUTION` | ใช้ผู้ให้บริการจราจรอื่นแทน TomTom (URL ต้องเป็น `https://` และมี `{z}` `{x}` `{y}`) | ใช้ TomTom |

**Key ของ TomTom** ถูกส่งไปที่เบราว์เซอร์เพราะ tile จราจรโหลดจากฝั่งผู้ใช้โดยตรง ให้จำกัด key ให้ใช้ได้เฉพาะโดเมนของเว็บใน TomTom Developer Portal ส่วน **key ของ GISTDA** ไม่ถูกส่งถึงเบราว์เซอร์

## แหล่งข้อมูลและความหมาย

| ข้อมูล | ต้นทาง | ความสดของข้อมูล |
|---|---|---|
| ระดับน้ำ | ThaiWater `public/waterlevel_load` | CDN cache 60 วินาที หน้าเว็บขอใหม่ทุก 2 นาที |
| ถนนน้ำท่วม | ThaiWater `public/flood_road` | CDN cache 2 นาที |
| ประตูระบายน้ำ | ThaiWater `public/watergate_load` | CDN cache 5 นาที หน้าเว็บขอใหม่ทุก 2 นาที |
| เขื่อน/อ่างเก็บน้ำ | ThaiWater `analyst/dam` (รายงานวันละครั้ง) | CDN cache 30 นาที ข้อมูลเก่ากว่า 3 วันแสดงเป็น "ข้อมูลเก่า" |
| พื้นที่น้ำท่วม | GISTDA flood WMS (ภาพเรดาร์ดาวเทียม) | ช้ากว่าเหตุการณ์จริง 1–3 วัน tile cache 1 ชั่วโมง |
| การจราจร | TomTom Traffic Flow (`relative0`) | รีเฟรชทุก 2 นาทีขณะเปิดชั้น |
| กล้องจราจร | iTIC / Longdo Traffic camera feed | รายชื่อกล้อง cache 30 นาที ภาพโหลดสดจากต้นทาง |
| กล้องระดับน้ำ | สำนักการระบายน้ำ กทม. 6 จุด, เทศบาลนครรังสิต | ภาพ JPEG รีโหลดทุก 10 วินาที (รังสิต ~2 นาที) |

**วิธีตัดสินว่าล้นตลิ่ง**
- ใช้ `storage_percent` ที่ ThaiWater คำนวณเอง: เกิน 100% = ล้นตลิ่ง, เกิน 70% = ใกล้ตลิ่ง, ไม่เกิน 30% = น้ำน้อย เกณฑ์นี้ตามคำอธิบายสีบน thaiwater.net แก้ได้ที่ `STORAGE_CLASSES` ใน `public/js/config.js`
- ถ้าสถานีไม่มีค่านี้ จะเทียบระดับน้ำกับระดับตลิ่งต่ำสุด (`min_bank`) ที่หน่วยงานเผยแพร่ ถ้าไม่มีทั้งคู่จะแสดง "ไม่มีเกณฑ์ตลิ่ง"
- ค่าที่วัดไว้นานเกิน 6 ชั่วโมงจะไม่ถูกนับว่าล้นตลิ่ง
- หมุดคือที่ตั้งสถานีวัด ไม่ใช่แนวตลิ่งทั้งเส้น
- ระดับน้ำเป็นเมตร รทก. (อ้างอิงระดับทะเลปานกลาง) ไม่ใช่ความลึกของน้ำบนถนน

**เขื่อนและประตูระบายน้ำ**
- % ของเขื่อนคิดจากความจุปกติ ใช้เกณฑ์กรมชลประทาน: เกิน 100% = เกินความจุ, เกิน 80% = น้ำมาก, ไม่เกิน 50% = น้ำน้อย, ไม่เกิน 30% = น้ำน้อยวิกฤต แก้ได้ที่ `DAM_CLASSES` ใน `public/js/config.js`
- ถ้าต้นทางไม่ส่ง % มา จะคำนวณจากปริมาณน้ำ ÷ ความจุปกติ ถ้าไม่มีทั้งสองค่า จะแสดง "ไม่มีข้อมูลปริมาณ" ไม่เดาตัวเลขขึ้นเอง
- ปริมาณน้ำไหลเข้าและระบายแสดงเป็นล้าน ลบ.ม. ต่อวัน ตามข้อมูลรายวันของ ThaiWater
- ต่างระดับของประตูระบายน้ำ = ระดับด้านรับ − ระดับด้านระบาย (ม. รทก.) แสดงเป็นข้อมูลอย่างเดียว ไม่ได้ใช้ตัดสินว่าอันตราย

**ความโปร่งใสของข้อมูล**
- **ข้อมูลเก่า:** ถ้าต้นทางล่ม API จะตอบด้วยข้อมูลชุดล่าสุดที่ดึงสำเร็จพร้อม `stale: true` และหน้าเว็บขึ้นป้าย "ข้อมูลครั้งก่อน"
- **ข้อมูลที่อ่านไม่ได้:** ถ้าต้นทางเปลี่ยนรูปแบบจนแอปอ่านไม่ได้ แอปจะขึ้นคำเตือน ไม่แสดงราวกับว่าไม่มีน้ำท่วม
- **ความลึกน้ำบนถนน:** แสดงเฉพาะเมื่อต้นทางระบุหน่วย
- **กล้องจราจร:** เก็บเฉพาะกล้องที่มี URL ภาพ HTTPS หรือวิดีโอผ่าน relay ของ iTIC กล้องที่หยุดส่งภาพชั่วคราวจะแสดง "ไม่มีสัญญาณ" เลือกจังหวัดที่มีข้อมูลได้ในหน้ากล้อง
- **กล้องท่าน้ำนนท์:** วิดีโอ HLS จากระบบตรวจระดับน้ำเทศบาลนครนนทบุรี เล่นเมื่อเปิดหมุดหรือหน้าดูภาพ พร้อมลิงก์ต้นทาง; ศูนย์กล้องถนนปากเกร็ดและกล้องระดับน้ำของกรมทรัพยากรน้ำมีลิงก์ไปยังเว็บหน่วยงานสำหรับกล้องที่ยังไม่มี stream รายจุดให้ฝัง
- **ความครอบคลุมกล้อง:** ฟีด iTIC มีเฉพาะจังหวัดที่หน่วยงานเผยแพร่ภาพพร้อมพิกัด ไม่มีฟีดเปิดที่ยืนยันภาพได้ครบ 77 จังหวัด ตัวเลขกล้องบนหน้าเว็บคือจำนวนรายการที่ผ่านการตรวจรูปแบบ URL ไม่ใช่จำนวนกล้องออนไลน์ที่รับประกันในขณะนั้น
- **ความเป็นส่วนตัว:** หมุดบ้าน ข้อมูลสถานีล่าสุด (เก็บไม่เกิน 24 ชั่วโมง) และการเปิด/ปิดชั้นข้อมูล อยู่ใน `localStorage` ของเครื่องผู้ใช้ ไม่ถูกส่งไปเซิร์ฟเวอร์

รายละเอียด endpoint ทั้งหมดอยู่ใน [docs/API.md](docs/API.md)

## Production

- **Security headers** (`vercel.json`):
  - `X-Frame-Options: DENY`
  - `Permissions-Policy` อนุญาตเฉพาะ geolocation
  - `nosniff` และ `Referrer-Policy`
  - CSP ในโหมด **Report-Only** script โหลดได้จาก cdnjs, unpkg และ jsdelivr เท่านั้น ส่วนรูปและวิดีโออนุญาตทุกโดเมน `https:` เพราะภาพกล้องมาจากหลายหน่วยงาน
  - เมื่อเปิด DevTools บน production แล้วไม่เห็น CSP violation ค่อยเปลี่ยน key เป็น `Content-Security-Policy` เพื่อบังคับใช้จริง
- **การ deploy เวอร์ชันใหม่:**
  - ไฟล์ HTML/JS/CSS ตั้ง `Cache-Control: no-cache` ให้เบราว์เซอร์ตรวจกับ server ทุกครั้ง (ตอบกลับเป็น 304 ถ้าไม่เปลี่ยน)
  - หน้าเว็บเทียบ `APP_VERSION` กับ `version` ใน `/api/config` ถ้าไม่ตรงจะโหลดใหม่เองหนึ่งครั้ง
  - JS/CSS โหลดจาก `/v/<version>/…` และ cache ถาวร (immutable) เวอร์ชันใหม่จึงได้ URL ใหม่ หน้าเว็บหนึ่งหน้าจึงได้ไฟล์จากเวอร์ชันเดียวกันเสมอ ไม่ปนกัน (build ล้มถ้าแก้ไฟล์โดยไม่ขึ้นเวอร์ชัน)
  - ขึ้นเวอร์ชันด้วย `npm version <x.y.z> --no-git-tag-version` ซึ่งจะอัปเดต `APP_VERSION` และ URL ใน `index.html` ให้เอง (`npm run build` ตรวจให้)
- **Library จาก CDN:** MapLibre 5.24.0 และ hls.js 1.7.3 ล็อกเวอร์ชันและตรวจ SRI ทั้งคู่โหลดเฉพาะเมื่อจำเป็น ถ้า Leaflet โหลดไม่ได้ รายการสถานียังใช้งานได้
- **Log:** ความผิดพลาดของต้นทางถูกบันทึกเป็น JSON ดูได้ใน Vercel Runtime Logs เช่น `water_upstream_failed`, `flood_wms_failed`, `road_flood_unrecognized` และ `traffic_cameras_upstream_failed` log ของ GISTDA ตัด key ออกแล้ว
- **ความเร็ว:**
  - สถานีหลายร้อยจุดวาดบน Canvas ตอน refresh ใช้ marker เดิมซ้ำ และสร้าง popup เมื่อเปิดเท่านั้น
  - หมุดประตูน้ำและเขื่อนสร้างเฉพาะบริเวณที่แผนที่แสดง เมื่อซูมออกจะเห็นเฉพาะเขื่อนขนาดใหญ่; เลือกรายการแล้วเลื่อนไปยังหมุดได้เสมอ
  - กล้องภาพนิ่งบนแผนที่โหลดเมื่อเปิดป๊อปอัปเท่านั้น และหยุดรีเฟรชเมื่อปิด
  - หน้ากล้อง: เล่นวิดีโอสดเฉพาะการ์ดที่อยู่บนจอ สูงสุด 4 สตรีม (คุณภาพต่ำสุดที่พอดีการ์ด) และหยุดทันทีเมื่อเลื่อนพ้นจอ ออกจากหน้า เปิดดูเต็มจอ หรือสลับแอป ถ้าเปิดโหมดประหยัดข้อมูล (Data Saver) จะไม่เล่นอัตโนมัติ
  - สตรีมที่ไม่มีภาพภายใน 15 วินาทีจะคืนช่องให้กล้องถัดไป และไม่ลองใหม่ 2 นาที
  - MapLibre ขนาด ~800 kB และ hls.js โหลดหลังข้อมูลสถานี จึงไม่หน่วงการแสดงสถานี

- ยังไม่มีข้อมูลฝนสะสม/พยากรณ์ และระบบให้ประชาชนแจ้งเหตุ ซึ่งต้องมีฐานข้อมูลและการตรวจสอบ
- กล้องกรมทางหลวงบางส่วนมีเฉพาะบน highwaytraffic.go.th ซึ่งไม่มี API สาธารณะ
- ถ้าจะมีผู้ใช้จำนวนมาก ควรสอบถามเงื่อนไขการใช้ฟีดกล้องกับ iTIC Foundation ก่อน

ผู้พัฒนาอ่านต่อได้ที่ [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) และดูประวัติการเปลี่ยนแปลงที่ [CHANGELOG.md](CHANGELOG.md)
